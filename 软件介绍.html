酷态科 10 号 Ultra · 电脑端工具

在电脑上监视、记录并控制你的充电头
版本 1.9.7 便携免安装 Windows 10 / 11 适配 AD1204U

一句话说明

把酷态科 10 号 Ultra（CUKTECH AD1204U）充电头的蓝牙数据完整搬到电脑上： 实时看四个口的电压 / 电流 / 功率、回看 1 分钟到 30 天的功率曲线、 统计累计用电量，并且能反向控制充电头本身 —— 开关端口、逐口开关快充协议、切场景模式、改息屏设置。

v1.9.0 起，家里的小米电风扇（Wi-Fi / miIO 设备）也并了进来 —— 同一个界面、同一个任务栏图标： 看它的运行状态并反向控制开关、无级调速、风型、摆风、定时、指示灯、提示音、童锁。 它不占蓝牙，和充电头、温湿度计互不干扰。

它补上了什么

这台充电头自带屏幕，米家 App 也能看实时功率。本工具补的是屏幕和 App 给不了的那几件事。

现有方式的短板本工具的做法
屏幕只有「当下这一秒」，一闪就过去了功率曲线可回看 1 分钟 ~ 30 天，插拔、换线、切档那一下的跳变都留档
米家 App 不留历史、不能导出按天的用电量账本：今日 / 累计 / 本次会话、近 7 天柱状图、四口分解、充电会话列表，可导出 CSV；面板大数字就是「度」，小字给 Wh 和 mAh —— 每口分解、充电会话、插拔记录三个清单也是这三种单位
屏幕上「正在用哪个协议」看不清握手协议 + 协商档位 + 端口协议码并列显示，每次出现新组合都记一行日志
米家只能打开手机看功率做成任务栏图标或任务栏内嵌面板，抬头就能看到
电脑和手机抢同一个蓝牙一键「让位给手机米家」，按分钟释放，到点自动收回

功能总览

实时监视

  • 总功率仪表盘，满量程 120 W，量程随读数自动抬升
  • 四口卡片：C1 / C2 / C3 / USB-A 的 V / A / W、协议徽章、协商上限
  • 实时推送通道：新采样落盘即推给界面，不是定时轮询

曲线与历史

  • 十二档窗口：1 / 5 / 10 / 30 分钟 · 1 / 2 / 3 / 4 / 6 / 24 小时 · 7 / 30 天（温湿度曲线读完温度计内置历史后，还会多出「90 天」「半年」「1 年」「全部」四档）
  • 点数上限：功率曲线 400 点、温度曲线 1200 点（v1.8.5 起分开设）；抽稀按时间分桶取均值 —— 温度是两种粒度混着的，按行分组会把每小时那条并掉、留下空白
  • 「平滑」只影响画出来的线，数据始终是原始值
  • 重启不留白：启动时回填最近 1 小时的原始点
  • 没有数据的时段画 0 而不是斜线（空档两端垂直掉零 / 抬升）

反向控制

  • 四口分别开关；场景模式：AI / 数码生态 / 单口 / 均衡
  • 协议开关 10 位：C1、C2 各 PD / PPS / UFCS，C3、A 各 UFCS / SCP
  • 息屏时间、屏幕语言、USB-A 小电流、锁定屏幕方向
  • 自动断电：某口有电压（≥5V）却几乎没电流（≤0.02A）持续 5 秒，自动关掉该口 —— 治「手机充满了还挂着」「线插着但没接设备」。门槛、等待时间、关闭后多少分钟自动恢复都可调；每次「有电压没电流」都记进「异常检查」板块，与该开关无关
  • 看温度 · 屏幕常亮：温度显示在充电头自己的屏幕上（触摸键切到「界面二 · 核心温度」）；这颗按钮把息屏时间设成常亮、并关掉空闲自动熄屏，让温度页不会自己黑掉，再按一次还原。蓝牙侧没有温度属性，按钮不涉及温度数值
  • 每次写入都回读确认，界面显示的就是设备真实状态

环境温度（外挂传感器）

  • 充电头的蓝牙属性里没有温度（官方规格表逐项核过），所以接家里的小米蓝牙温湿度计 2（LYWSD03MMC）——已有设备，零成本
  • 不需要密钥、不需要刷机：原厂固件就能连上读 GATT。默认每 90 秒连一次、读一次就断
  • 温度、湿度、信号强度同卡显示；数据陈旧会标「多久没更新」并把数字变灰，不拿旧值冒充最新值
  • 曲线把温度（橙，左轴）和湿度（青，右轴）画在一起，共用一条时间轴；空档处直接断开、不补 0
  • 把温度计自己存的历史读回来：设备内部每小时记一条该小时的最高/最低温湿度，断电不丢。点一次「读取设备历史」，几分钟就能把约半年的存量（实测 156 天 / 3800+ 条）灌进曲线——软件还没开始运行的那几个月也能看到
  • 读完区间里会多出「90 天」「半年」「1 年」「全部」四档；时间轴刻度随跨度自动换格式（时:分:秒 → 月-日）
  • 每小时一条，画成一段（v1.8.3；v1.8.15 去掉橙色阴影带）：设备记录覆盖的是刚走完的那一小时，曲线把它画成横跨一小时的一段线而不是孤点 —— 切到 30 分钟窗口也不会再"只有一两个点、其余全空白"；该小时的最高/最低仍在悬停提示里，但不再铺橙色阴影带（上下沿像多出来的一圈描边）
  • 温湿度曲线有自己的「平滑」开关（v1.8.15）：与功率曲线那个独立、默认开启；只影响画线，取消勾选就看原始台阶
  • 温度计卡片可以收起（v1.8.15）：标题右侧「收起 / 展开」—— 用不上温度计时收成一行标题（曲线和设置都还在），收起时标题行显示读数摘要，状态会记住
  • 读完历史就覆盖旧数据（v1.8.2）：设备每小时记的是该小时最高/最低，本应用采的是 90 秒瞬时值，两种粒度混着画会让「当日最低~最高」忽宽忽窄 —— 读完历史会把本机自己采的读数全部丢掉，只留设备内置历史这一套来源（之后新采的照常往后接）
  • 按天看温湿度（v1.8.1）：卡片右上角「按天」把曲线压成一天一个点 —— 纵轴是当天均值，橙色阴影带是当天最低 ~ 最高；下面另给一张按天明细表（日期 / 均温 / 当天最低~最高 / 均湿 / 采样点数，最近 31 天）
  • 打开『按天』时若窗口短于 7 天会自动跳到 7 天（一天一个点，短窗口画不出东西）；表里的「采样点数」用来自证今天只有半天数据
  • 读历史是慢操作，期间独占设备蓝牙：采集先暂停、读完自动恢复，失败自动重试 3 次。读之前请完全退出手机米家——温湿度计是单连接设备，被连着时就不再广播

小米电风扇（Wi-Fi 设备）

  • 读的是家里的米家直流变频落地扇（dmaker.fan.p5 这一类）。它走另一条路：充电头与温湿度计是蓝牙，风扇是 Wi-Fi（miIO） —— 局域网 UDP 直连（端口 54321，AES-128-CBC 加密），不经过米家云
  • 不占蓝牙：电脑连着充电头时风扇照常能读能控，手机米家也能同时控制它（不用像充电头那样「让位」）。由独立的 fan_collector.py 采集，同样是「可失败」设计 —— 风扇连不上只是这张卡灰掉，蓝牙那两台一点不受影响
  • 不用单独登录：点一次右上角「登录小米云」扫码，同一次授权会把充电头的 12 字节蓝牙密钥和风扇的局域网 IP + 16 字节密钥一起取回来，分别存 data\cuktech.token 与 data\fan.token
  • 只读状态与开关，不做功率 / 电量：这台风扇没有任何电参量属性可读（规格表逐项核过：没有功率传感器、没有电量统计、也没有「已运行多久」），所以卡片上的大数字位放的是它的开关状态（运行中 / 已关闭 / 未运行）—— 不做功率、不做用电量、也不画曲线。v1.9.0 曾按「额定功率 × 档位比例 × 自然风系数」推算瓦数再积分出用电量，2026-10-11 按用户要求整体删掉 —— 推算出来的数看着像实测，反而误导
  • 反向控制：开关、无级调速（1~100 滑条）、档位（1~4）、风型（自然风 / 直吹风）、左右摆风、摆风夹角（30 / 60 / 90 / 120 / 140 度）、定时（0~480 分钟）、指示灯、提示音、童锁。每一次写入都会回读确认 —— 界面上的开关状态是设备读回来的值，不是「我以为写成功了」；写入期间开关变半透明（同一时刻只发一条命令），卡片里会写一句「… → 回读 X，一致」
  • 设置与自检：轮询间隔（默认 2 秒，可调 0.5~30）、「连接自检」（连一次、把全部属性读回来就退出，不进常态轮询）、「局域网发现」（广播一轮看网上有哪些 miIO 设备 —— 只能确认它在不在网上，拿不到密钥，所以它不是判断在线与否的依据）
  • 风扇原始属性：值不经过任何换算，出问题时能一眼分清「设备没回」还是「界面没画」；末尾带通信计数（超时 / 重传，一直涨说明网络或设备不稳）。卡片标题右侧的「收起 / 展开」和温度计那张一样，用不上时可以收成一行标题
  • 它读不到什么：风扇没有电量统计属性、没有功率传感器、也没有「已运行多久」，所以本工具不显示它的功率与用电量 —— 能看到的只有开关、档位、风型、摆风这些状态位。想知道准确耗电，得在插座上加个计量插座

用电量统计

  • 对瞬时功率做时间积分，间隔超 60 秒的段落整段丢弃
  • 按天分桶存盘，重启不丢；今日 / 累计 / 本次会话
  • 面板大数字就是度（电费单口径），小字同时给 Wh 和 mAh（充电宝上标的那个「毫安」：10000 mAh ≈ 37 Wh @3.7 V）
  • 每次插拔单独记账：某个口从插上到拔掉算一次，这次充了多少单独记一条（三种单位 + 时长 + 峰值 + 协议）；判定靠端口字的「在用」位而不是功率，拔出还要连续 5 秒确认，接触不良闪断不会把一次充电切碎
  • 4 个端口卡上各有一行「本次充电」：正在充是实时值（带「充电中」），电量旁边同时显示这次已经充了多久；拔掉后固定成结算值，挂到这一口下次充电才刷新
  • 近 7 天柱状图 + 四口分解 + 充电会话列表
  • 三种 CSV 导出，带 UTF-8 BOM，Excel 打开不乱码

桌面集成

  • 任务栏功率图标，悬停看四口，右键菜单操作
  • 三种模式：仅总功率 / 四口轮流 / 一行面板嵌入任务栏
  • 充满提醒与掉线提醒（任务栏气泡）
  • 开机自启动可选，放启动文件夹，不改注册表；开机全程不弹任何窗口（v1.8.23 起快捷方式直连 node，不经过 .bat），后台运行档只留任务栏托盘图标
  • 双击就是启动：软件已经在跑时（窗口被关了、只剩任务栏图标），双击不会另起一个实例，而是把已有窗口唤到前面；要升级先右键任务栏图标选「退出」
  • 磨砂固定开（v1.8.2 删掉了开关）：窗外糊成柔和底色 + 系统圆角；观感强弱用右上角透明度滑块调（往左更透、往右更实）
  • 「失焦」透明度可以单独调：顶栏那条「失焦」默认 70%，与聚焦那条同口径（0 = 全透 ~ 100 = 不透明）；显示「跟随」时与聚焦那条一致，拖动即预览、双击回跟随。失焦时窗外仍然模糊（v1.8.20 起聚焦/失焦同一种材质）；预览与真失焦走同一条渲染路径，拖动预览成什么样，切走之后就是什么样（v1.8.21）
  • 窗口顶部两条贴边的圆角玻璃条（拖动条 + 页头），页面内容从它们下面滚过时被模糊
  • 窗口本体是圆角玻璃（系统圆角，约 8px），圆角外没有直角残留；窗口边缘可拖动缩放，也可用界面里的三档尺寸

让位给手机米家

  • 充电头没有 Wi-Fi、不支持蓝牙网关，BLE 同时只允许一个中心端
  • 点一下 → 填 1–120 分钟 → 立刻完全释放蓝牙
  • 到点自动收回，也能提前点「收回蓝牙」

技术实现

部分说明
协议小米 MiOT over BLE（服务 0xFE95），设备 product_id 0x660E
后端server.js（Node，约 4000 行）：HTTP API、采集器进程管理、用电量账本、历史落盘
采集器collector.py（Python）：BLE 连接与轮询，另带 --sweep 扫属性表、--probe 跑请求形状矩阵
风扇采集器fan_collector.py + vendor/miio_lan.py：走 Wi-Fi 局域网（miIO / UDP 54321 + AES-128-CBC），与蓝牙链路互不影响；--probe 只连一次做自检，不进常态轮询
界面web/ 原生 HTML + CSS + JS，无构建步骤，改完刷新即生效
托盘tray.ps1：任务栏图标与气泡通知，由后端自动拉起
协议库vendor/ 第三方 MiOT 协议实现（MIT 许可，取自 zuyan9/ha-cuk-ble）
界面开在浏览器的 app 模式窗口里（无地址栏、无标签页），观感等同原生程序。
授权只做一次：扫码从小米云取这台设备的 12 字节蓝牙密钥，之后全部本地直连，不需要填任何地址。
登录的 TLS 口径：Python 3.13 起客户端默认给 HTTPS 打开 OpenSSL 的严格模式，它比浏览器严得多 —— 小米证书链里只要有一张 CA 证书的 basicConstraints 没标成 critical 就直接判死。程序只关掉那一面旗子，CA 校验与主机名校验照做；登录弹层的「网络自检」会现场拉一遍证书链，区分「本机正常 / 严格模式误判 / 网络被中间人解密」，报告写 data\tls-report.txt。
数据分两层落盘：原始采样按天一个文件（保留 7 天）+ 每分钟降采样一行（与电量账本同寿命，400 天）。

隐私

  • 扫码登录只用于从小米云取这台设备的蓝牙密钥，密钥存在本机 data\cuktech.token，不上传到任何别的地方。
  • 历史采样、用电量、识别记录全是本机文件，放在 data\；把 data\ 整个删掉就等于恢复出厂状态（要重新扫码）。
  • 充满 / 掉线提醒只出现在任务栏气泡和应用日志里，不发往任何外部服务。

三分钟上手

  1. 把整个文件夹解压到任意位置（不要只解压单个文件）。
  2. 双击「启动酷态科10号Ultra.bat」，会弹出应用窗口。
  3. 点右上角「登录小米云」，用手机米家 App 扫二维码并确认授权（只需一次）。
  4. 等 10–30 秒，界面开始出数据。
开始前请确认：充电头插着市电、屏幕亮着；电脑蓝牙可用、离充电头近一些； 设备绑定在你扫码的那个米家账号名下；如果米家 App 正连着它，请先在米家里断开 —— 蓝牙同时只允许一个中心端连接。

已知边界（诚实清单）

做不到的事原因
读线缆 eMarker 身份USB-PD 协议里没有任何命令能让外部查询「源从线缆读到了什么」，蓝牙属性表里也不存在。替代用法：同一条 20 V 合约下换线，对比「协商上限」数字的变化间接判断
读充电头温度充电头屏幕能显示温度（内部有 NTC），但温度没有任何对外出口：设备蓝牙侧只有一个服务、21 个属性（逐项核过，没有温度项），第三方逆向文档与 191 行 BLE 抓包同样没有，残留的 2.14 enter 写入实测无反应，GATT 厂商服务只写不读。能做的只有「看温度 · 屏幕常亮」——把屏幕点亮着，让你看它自己的温度页
定时关闭官方规格表把 2.9–2.12 记为定时关闭属性，但实测这台固件没有下发这四项（请求整批被静默丢弃），米家 App 里也没有对应开关
显示手机 / 设备品牌充电头屏幕上的品牌名不走蓝牙，MiOT 属性表里没有品牌 / 型号字段。本工具能显示的是蓝牙这条路上拿得到的口径：握手协议 + 协商档位 + 端口协议码
手机和电脑同时用BLE 单中心端，硬件层面互斥，只能用「让位给手机米家」轮流
其他型号的充电头只适配 AD1204U（蓝牙名形如 njcuk.fitting.ad1204）
风扇的功率 / 电量这台风扇的属性表里没有任何电参量（规格逐项核过：没有功率传感器、没有电量统计、也没有「已运行多久」），所以本工具不显示它的功率与用电量 —— 只回读状态并做反向控制（v1.9.0 曾按档位推算，2026-10-11 已整体删除）
靠广播找风扇家里路由器一般不转发无线客户端之间的广播，风扇的 Wi-Fi 为省电还会休眠漏包 —— 「局域网发现」扫到 0 台不代表离线，判断在线请看卡片上的链路状态

适用人群

  • 想搞清楚「这根线 / 这台手机到底跑在多少瓦、走的哪个协议」的人。
  • 想给充电头做长期用电统计、并导出成表格的人。
  • 想让充电头数据常驻在电脑桌面上、随时瞄一眼的人。
